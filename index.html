💾 Native Web Storage

Native interfaces provided by the browser that leverage OS-level storage capabilities.

Cookie

Ultra-lightweight data (< 4KB) exchanged via HTTP headers. Automatically included in requests but has the lowest performance.

WebStorage

LocalStorage (persistent) & SessionStorage (session-based). 5MB limit. Synchronous operations can cause UI freezing with large data.

IndexedDB

High-capacity asynchronous object store. Supports indexing and transactions. Best for data over several hundred MBs.

OPFS

Origin Private File System. Sandboxed high-performance file system API. Used internally by SQLite WASM for actual file I/O speeds.

WebSQL

A legacy standard no longer supported. Replaced today by the SQLite WASM + OPFS combination.

📚 Wrapper Libraries

High-level libraries that simplify usage and add advanced features on top of Native APIs.

Dexie.js

A lightweight wrapper for IndexedDB. Simplifies complex IDB syntax and provides powerful querying capabilities. (Base: IndexedDB)

localForage

A polyfill library that automatically selects the best storage in order: IndexedDB, WebSQL, then LocalStorage. (Base: Async IDB)

SQLite (WASM)

The SQLite engine compiled to WebAssembly. Combined with OPFS for a full relational SQL DB experience on the web. (Base: OPFS/IDB)

PouchDB

An offline-first DB implementing the CouchDB protocol. Features automatic synchronization with servers. (Base: IndexedDB/WebSQL)

store.js

A compatibility-focused lightweight wrapper supporting almost all browsers, including legacy ones. (Base: LocalStorage)

📦 Compression Engines

Core algorithms designed to save storage and optimize data transfer.

Gzip / Deflate

Standard compression methods. Modern browsers use the Native CompressionStream API for ultra-fast processing.

Brotli

Offers significantly better compression ratios than Gzip for text but requires more resources during compression.

zstd

Next-gen algorithm by Facebook. Offers the best balance between compression ratio and speed. Implemented via WASM.
